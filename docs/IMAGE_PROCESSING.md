# Original image-processing measurement scope

The study's service-time evidence is generated by the **fixed external visual-place-recognition pipeline** below. This document specifies the reported execution boundary and the assets needed for an independent acquisition run. It does not present a new or unverified runnable pipeline as equivalent to the original GPU execution.

1. Acquire benchmark imagery and native positives directly from the four provider resources in `DATA_SOURCES.md`, under the respective terms. Use the study's fixed development and external query/gallery selection, not a new random split.
2. Generate **CosPlace ResNet50**, 512-dimensional, L2-normalized global descriptors and freeze the ranked **top 100** candidates per query. The historical source fingerprint includes CosPlace commit `52b56e95ea62245281281f3bafd7b9390d19a0fd`. Upstream software: https://github.com/gmberton/CosPlace.
3. Use **DISK** features, 1,024-pixel resize with a maximum of 2,048 keypoints; **LightGlue** with filter threshold 0.1, historical source commit `eb42fee2d71449efb0aa5c10549752b5d75384d8`; **USAC/MAGSAC++** with 3 px threshold, max 10,000 robust iterations, confidence 0.999 and OpenCV seed 20260825. Upstream: https://github.com/cvg/LightGlue, https://github.com/cvlab-epfl/disk, https://github.com/opencv/opencv.
4. Accumulate geometric evidence for the nested verification depths **5, 10, 20, 50**. Use the common six-ranking reciprocal-rank reranker (offset 60; support cutoffs 5 and 10). All policies must share the identical prefix top match and underlying feature values before comparing stopping rules.
5. Apply the immutable fitted PlaceGate parameters (identifier `GPV` in the sealed configuration) in `configs/frozen_protocol.json` and the frozen comparator thresholds `0.47164774278243266` (Progressive Inlier) and `0.45321262287588476` (Full PEAV). The policies must receive the same top-100 and prefix observations.
6. Time **each of seven policy executions separately**, in deterministically rotated orders after a ten-query warmup. Warm/cached local reference features for the 50 candidates before the timed policy service. Synchronize CUDA around service timing; time query decoding, query local feature extraction, precomputed candidate access, local matching, robust geometry, prefix construction and controller decisions. Do **not** include training, global descriptor retrieval, or reference feature-cache creation.

## Hardware used to produce the released records

| Dataset | GPU | Runtime of original records |
|---|---|---|
| Freiburg Across Seasons | NVIDIA L4 | PyTorch `2.14.1+cu130`, CUDA `13.0`, Python `3.13.16` |
| Daejeon520 | NVIDIA A100-SXM4-80GB | PyTorch `2.14.1+cu130`, CUDA `13.0`, Python `3.13.16` |
| Alderley Day/Night | NVIDIA A100-SXM4-80GB | PyTorch `2.14.1+cu130`, CUDA `13.0`, Python `3.13.16` |

The original matching model weights, raw source images, original path-based gallery and selected-query manifests, cached reference features and executable original GPU orchestration environment are **not contained** in this numerical reproduction release. Consequently **no end-to-end image-to-reproduced-ms command is claimed or validated**. A new GPU measurement, even at the same policy depths, cannot be assumed to reproduce the archived milliseconds.

The public, tested commands in the README operate only on the archived numerical evidence and are independent of CUDA and third-party matching implementations.
